# 原生版界面与动画基线

## 技术基线

- Godot 4.7.2、Compatibility 渲染器、横屏沉浸式全屏；主目标 OPPO Pad 3 Pro 12.1 英寸，逻辑视口 1600×1129 并按 `canvas_items` + `expand` 缩放；目标平板优先 120 FPS，逻辑帧按游戏类型固定。
- `PlaygroundUI` 提供主题、字体、颜色、按钮、圆角面板、标签和转场；游戏只组合组件，保持原生。
- `NativeGameScreen` 统一左右纸边暂停入口、儿童状态、暂停、说明、声音、系统返回和实时补存；`LobbyGameCard` 负责大厅卡片、继续/新开与拖动。
- 不使用 WebView、DOM、CSS、Vite 或浏览器路由。
- 不引入第三方运行时 UI/动画框架；统一使用 `MotionKit`、Godot Tween/AnimationPlayer、AudioServer 和原生 Control。

## 共享交互框架（2026-11 新增）

- `src/ui/interaction/` 是全局交互层：`GestureRecognizer`（tap/长按/拖拽状态机）、`InteractionController`（输入优先级仲裁：弹窗500>拖拽400>选中300>棋盘100）、`DragController`（跟手 ghost 与落点/回弹）、`SelectableGroup`（选中态）、`DialogManager`（统一弹窗）、`PressFeedback`（按压回弹）、`SfxMap`（语义事件→合成音效映射）。
- main 作为 `main_hub` 组暴露 `ipc` 与 `dialogs`；游戏与自绘表面通过 `get_first_node_in_group("main_hub")` 访问，弹窗打开期间用 `ipc.is_blocked_by_dialog()` 静默游戏输入。
- 弹窗规范：S/M/L 三档宽度（0.38/0.56/0.78，含像素上限与安全边距），高度随内容展开；圆角 28、2px 描边、遮罩 0.38、进出 scale+淡入约 200/160ms、关闭后焦点还原；返回键统一先关弹窗栈顶。正式 `DialogManager` 与游戏内备用入口必须复用 `DialogPanel`，不能维护两套内容或按钮布局。
- 弹窗动作固定分组：一项主操作整行；两项严格等宽；三项为两项辅助同行、主操作独占下一行；更多选项放入正文选择区。动作区禁止使用 `HFlowContainer` 自动换行。
- 暂停工具页使用专用 `pause` 布局：可选“本局工具”区之后固定显示 2×2 通用工具格，最后是单独整行的“继续游戏／接着读”。系统工具始终保持横屏正向。
- 弹窗采用固定标题栏、内容自适应正文和固定操作区；表单类弹窗通过 `fit_content` 在一张纸面内展开，较宽平板使用两列字段区，不再把字段塞进内部滚动框。
- 自绘表面（board_surface、quiz_stage）输入统一走手势状态机，触摸与鼠标双通道并去重；触摸抬起/暂停/弹窗时必须清理 hover 与按压残留。
- 大厅：`SmoothScrollContainer` 覆盖整个大厅页面，品牌栏、标题、卡片和底部说明一起滚动，滚动条隐藏；提供阻尼惯性与边界回弹，原创封面经 `ArtLibrary.cover_texture` 从图集直接裁切；排序为增量重排（不整树重建），进入整理模式后长按拖动，普通滑动仍只滚动。
- 答题：题干使用独立纸卡，视觉区和三个点击答案卡分层排列；禁止把拖拽投放作为必需交互。所有游戏默认全屏沉浸，隐藏顶栏、大玩家条、长句提示、教学条和底部工具，但保留轮次、选中、合法落点、答题反馈和系统阻塞等事实状态。
- 沉浸模式使用左右专用纸边作为暂停入口。抬手轻点纸边或按系统返回键时，依次补存、停止朗读和音效、清理触点、冻结规则与动画、打开暂停工具页；工具页不自动消失。规则、声音、重开确认和离开确认形成明确子页，关闭或取消回到暂停页。
- 沉浸内容必须使用安全区：军棋使用独立横纵格距和完整棋面；唐诗、答题、故事按屏幕高度放大字号与行距；必要按钮放在独立底栏，不覆盖正文。
- 双人棋类以 OPPO Pad 3 Pro 横屏 3000×2120（逻辑 1600×1129）为准：玩家 1 坐左短边，玩家 2 坐右短边，两人的连线沿 3000 长边。左方内容顺时针 90°、右方逆时针 90°，朝向随阵营固定，换手不翻屏。象棋、军棋、斗兽棋的双方阵地位于左右两端。
- 选中棋子后的合法落点绘制在棋子之上：红点表示可走空格，红圈表示可吃目标；马用多个“日”字路线，象用“田”，车、炮、士兵、工兵和狮虎跳河使用各自路径提示。提示层不拦截触摸，暂停时停止呼吸动画。
- 军棋使用浅色玩具军棋桌面与清晰的靛蓝铁路、普通道路和场地图标；棋子以大号军衔数字、兵种名、九格刻度和原创兵种图形完成远距离识别，红蓝同时依靠边框、底纹和圆点/菱形区分。
- 口算、拼音、规律、动物、数学小练本的轮流答题，以及记忆翻翻乐，按两人坐在长边同侧处理，题面、选项、讲解和卡面保持横屏正向。

## 完整体验重构（2026-11）

- 大厅以“实体玩具柜＋绘本”为统一视觉方向；卡片主操作严格对应“开始／继续”，继续局直接进入恢复流程，新开一局使用独立入口。
- 开局使用一张准备纸卡，同时呈现模式、参与者、适用难度、座位摘要和开始条件；人数不足时固定操作区的开始按钮直接禁用。
- 答题游戏移除左右大侧栏，题干、视觉、三选一和讲解在同一稳定舞台中排列；答题后保留正确项、所选项和解释，直到点击“下一题／查看成绩”。
- 记忆翻翻乐整盘固定在可用区域内，不使用纵向滚动；当前儿童与“再翻一张”状态保留在卡牌下方。
- 唐诗把抽背诗卡作为主内容，评价后由同区动作替换为“下一首”；全库与路线从选诗入口进入。
- 故事馆书架每篇只保留“打开”，进入阅读后才提供系统朗读；朗读、阅读设置和书签都在固定底栏可达，未点击播放时不会自动开口。
- 数独采用左棋盘、右数字盘；选格高亮关联行列宫，冲突同时圈出，提示先说明线索再允许填格，撤回、擦除和换题均保存状态。
- 四类棋共用按下预览、抬手提交、滑出取消的输入规则；象棋和军棋把阻挡原因、交战结果与将军状态留在棋盘，而不是只依赖短 toast。

| 答题练习 | 唐诗、数学小练本、口算、拼音、规律、动物 | 题卡入场、答案按压、知识讲解停留、手动下一题 |
| 记忆棋类 | 记忆翻翻乐、五子棋、军棋、斗兽棋 | 翻牌、图形棋子、落下、移动、合法位置发光、胜负连线与回放 |

## 模式与交互

- 每款游戏在单张准备页选择模式、儿童和适用难度；模式、参与者和阶段一起进入会话键。“继续”直接恢复唯一会话，多个会话先选局。
- 单人闯关有章节地图、星级和逐关保存；棋类残局使用固定局面和提示，不调用运行时 AI。
- 答题讲解与答案保留到手动点击“下一题/查看成绩”；棋类和记忆游戏按各自换手规则转换。
- 所有主要按钮至少 56dp，辅助触摸至少 48dp；密集棋盘提供按住预览。游戏内通过纸边或系统返回进入暂停，暂停页再选择继续或回大厅。
- 各游戏主按钮沿用 `games.json` 的专属主色并由亮度自动选择白字或深墨字；辅助按钮统一奶油白 `#fff9ed`、暖灰描边和深墨文字。重开、删除使用琥珀提示样式并二次确认；操作按钮不使用浅红、绛红或玫粉底板。
- 动画服务于操作反馈：按钮约 70–130ms，弹窗约 120–180ms，翻牌约 260ms，棋子移动约 240–400ms。
- 暂停停止逻辑计时和场景 Tween；恢复后不重复执行动作或结算。
- 故事馆采用单人自由听读，完整正文与逐字拼音内置，正文按单纵向长卷滚动，情节插画以约四五行高度的左右浮动块嵌入文字，图片结束后的下一行恢复整宽。朗读使用安卓平板自带中文系统 TTS；不下载音频，不提供 MP3 缓存入口。朗读逐段推进并高亮当前段，暂停后从当前段继续；后台和锁屏停止朗读，回来手动接着听。
- 1604 张原创故事插画独立部署，不进入 APK 和内容包。进入一篇故事时下载该篇 2–3 张 WebP，逐张校验大小与 SHA-256，缓存到 `user://story-images/`；缺图时正文先显示，下载成功后按同一阅读锚点重排。阅读锚点、朗读段落和跟随状态分别保存，手动滚动后不会被朗读抢回。
- 插画尚未到达时保留四到五行高度的浮动纸框，文字绕框排版；下载完成后原位换图，避免页面突然由单列变成绕排。本机缓存限制为 64 MB，超限时按最近使用时间淘汰，最多同时下载三篇。
- 界面图标、封面、卡背、棋子和内容图形使用原创资源。`ArtLibrary.semantic_picture` 与 `OriginalGlyph` 提供语义图标和内容图形，`ArtLibrary.cover_texture` 提供封面图集；按钮和状态不直接用 emoji 或文字符号充当图标。旧第三方资源仅供历史兼容审计。
- 故事正文按完整多段叙事制作，不采用两句梗概；段落变化后必须重新生成逐字拼音。系统音色由平板决定，没有中文 TTS 时明确提示家长安装或切换中文语音。
- `StoryText` 按段缓存字形布局，用原生 Canvas 绘制正文与拼音，不为每个字建立节点；字号、拼音或宽度改变时重排。书架每页最多 18 篇，避免同时建立整库卡片。
- 中文固定使用随包 Noto CJK；题目数据里的 emoji 字符仅作为稳定内容标记，运行时由 `ArtLibrary` 转成原创图形，不直接显示系统 emoji。
- 卡片和任何 `Container` 子节点禁止用位置动画入场；只动画透明度、缩放或独立浮层。
- 游戏优先 120 FPS；持续掉帧时降低粒子和 3D 质量，不主动降低目标刷新率。岛屿 3D 静止时停止刷新。

## 目标平板与开场

### 中国象棋

- 红帅黑将、红先黑后，完整支持车、马、炮、相/象、仕/士、兵/卒与将/帅走法；炮必须隔一子吃子，马腿、象眼、九宫、过河与将帅照面都按标准规则校验。
- 每步检查己方是否被将军，吃掉对方将帅获胜；固定一步杀关卡不调用运行时 AI。
- 棋盘使用独立 9×10 交叉点布局、楚河汉界与九宫斜线，红黑棋子使用不同字形和颜色；默认沉浸式，轻点左右纸边或按系统返回进入暂停工具页。
- 对局、悔棋、关卡和将军状态通过统一 SaveStore 实时保存，重新打开后从当前局面继续。
- 红方固定使用红色“帅、仕、相、兵”，黑方使用深色“将、士、象、卒”；初始各 16 子、五枚兵卒，棋子过河、换手与恢复存档不改变阵营。

### 数独小游戏

- 32 道固定题库：8 道 4×4 四宫格入门、24 道 9×9 标准数独，全部由内容源脚本生成并验证唯一解。
- 点击格子再点数字输入；题目数字不可修改，重复数字用橙色标记，支持擦除、提示、换题和关卡地图。
- 棋盘按宫格粗线分组，数字按钮随 4×4/9×9 自动切换；横屏采用左侧棋盘、右侧数字盘，规则与暂停通过左右纸边进入。
- 填写、提示、擦除和完成都实时写入统一 SaveStore，重新打开继续原局。

- 主要目标：OPPO Pad 3 Pro 横屏。官方 OPD2402 参数为 12.1 英寸、3000×2120、7:5、最高 144Hz、303 PPI、LCD；13.2 英寸 3392×2400 平板只作为可选回归兼容目标。
- 运行时读取 `DisplayServer.screen_get_size()`，以实际屏幕为准；布局使用安全边距与弹性容器，不硬编码 3000 或 3392 像素。OPPO Pad 3 Pro 主基线是 1600×1129 逻辑视口，用于覆盖 3000×2120 物理分辨率。
- `pnpm native:audit` 默认只生成用户 OPPO Pad 3 Pro 的 3000×2120 截图；1180×800 与 3392×2400 仅在用户明确要求对应尺寸时通过 `KIDS_UI_SIZE` 选择。棋类包含选子、双方走子、吃子和恢复状态；`-left-seat/-right-seat` 为同一画面的观察方向图。
- UI 审计检查全部棋盘位置的绘制/点击映射、边缘棋子完整性及状态恢复；脚本解析或实例化失败时必须非零退出，禁止以空白截图判通过。布局与性能报告写入 `build/ui-audit/`；桌面数据不代表真机系统手势和性能已验证。
- 启动序列：`LYNOTE / 童心制作` 厂牌入场 → 标题/副标题与光环动效 → 淡入大厅。约 3–4 秒，可触摸或确认键跳过。
- 开场动画使用原创文字、圆环、星点和合成的 `studio`/`title` 音效，不复制腾讯、TiMi 或任何现成游戏的商标和素材。

## 来源与素材

- `content-src/references.json` 记录参考项目、查询时的 Star 数、授权和采用方式。
- `content-src/licenses/original-art.json` 记录本轮原创素材；Kenney、OpenMoji 和 Noto 等旧来源记录保留供历史审计。
- 本轮 UI 图标、封面、卡背、棋子外观和内容图形为项目自绘或原生生成；Noto CJK 字体继续使用 OFL-1.1。
- Godot 升级前在独立分支运行规则、存档、两档平板和更新回归，不直接覆盖稳定版本。
