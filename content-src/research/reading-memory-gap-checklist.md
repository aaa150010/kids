## 实读范围判定

- 记录显示 47 个来源均有有效正文（HTTP 200，`body_valid=true`），并保存正文长度及相关交互证据；因此按“成功读取过有效正文的独立文件”口径，count **47** 成立。
- 阅读方法明确为“相关 API 描述、属性、方法或源码函数及上下文”，`read_scope` 为“相关交互段落与函数上下文”。部分证据还标明具体行号或“全文”。这支持相关段落/函数的实读，但**不能据此声称 47 份大型文件都逐行精读**。
- 所以，四款的 count/entry 在 JSON 内部完整对齐；若“完整实读”意指每份源文件全文逐行审阅，现有记录不足以证明该口径，须将其表述为“有效正文取回，按相关交互段落实读”。
- 来源清单按 `sources` 中 47 个 ID 计数；游戏 entries 仅关联各自的 20 个来源。未发现 entry 缺 source 或同一游戏重复关联 source 的情况。
